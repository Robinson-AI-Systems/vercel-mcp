## 1. The service's API surface (playbook step 1)

### 1.1 Shape of the API

- **REST + JSON** at `https://api.vercel.com`, bearer-token auth (`Authorization: Bearer <token>`).
- **Versioned per operation, in the path** (`/v9/projects/{idOrName}`, `/v10/projects/{idOrName}/env`, `/v13/deployments`).
  There is no account-wide API version like Stripe's. Vercel adds a new path version when an operation changes and keeps
  older versions answering for a time; the old toolkit's use of older versions (§2.3) shows the drift this causes.
- **OpenAPI description:** `https://vercel.com/openapi.json` (also served at `https://openapi.vercel.sh/`). Its
  `info.version` is a constant (`0.0.1`, confirmed from `@vercel/sdk`'s generated `openapiDocVersion`), so it is **not** a
  usable version marker. The plan therefore vendors a dated snapshot with its SHA-256 and operation count
  (`docs/designs/BATCH-A.md` A-4) and treats each operation's path version as the pin.
- **Team scope:** `teamId` or `slug` query parameter on nearly every operation. Team- and project-scoped tokens infer the
  team (and project) and do not need either parameter; a full-account token needs one to reach a team.
- **Pagination:** cursor style (`limit`, `until`/`since`, response `pagination.next`), not uniform across operations
  (the project list returns either an array or `{ projects, pagination }`, per the getting-started page).
- **Errors:** `{ "error": { "code", "message", … } }`; generic codes `forbidden`, `rate_limited` (with
  `limit.remaining/reset/resetMs/total`), `bad_request`, `internal_server_error`, `not_found`, `method_unknown`; domain
  codes `price_mismatch`, `not_available`, `conflict_aliases`, `custom_domain_needs_upgrade`, `failed_to_add_domain`;
  environment codes `env_key_invalid_characters`, `env_value_invalid_length`, `env_too_many_keys` (errors page).
- **No idempotency keys.** Nothing in the reference accepts one. Retries of writes must be made safe by this server
  (contract §6: the change log's request key within 10 minutes, and a state check before retrying a write whose outcome
  is unknown).
- **Rate limits are per operation** (the limits page lists ~200 named limits with count, window and scope `owner` /
  `user` / `team` / `project`). Examples that matter here: project env-var creation 120/min and deletion 60/min;
  deployments retrieval 500/min per user; deployments per hour 450 (Pro); deployments per five minutes 120 (Pro);
  domain creation 120/hour; DNS record creation and update 50/min; team update 100/hour; team slug change 6/week;
  team member update 40 per ten minutes; production deployment (promote) 500/min. Over a limit → HTTP 429 with code
  `rate_limited` and a reset time. The client honours the reset time and never retries in a loop (A-4).

### 1.3 Environment variable types (changed in 2026)

Vercel now presents two user-facing kinds, **Config** (readable after saving) and **Secret** (write-only after saving).
The API carries both a legacy `type` (`plain`, `encrypted`, `sensitive`, `secret`, `system`) and a newer
`visibility` (`config` | `secret`); legacy rows omit `visibility`. Existing Sensitive variables are treated as Secret;
Secrets are now allowed in Development; the legacy "enforce sensitive" team policy is deprecated and replaced by
"Separate Production Secret Values" (`disjunctiveProductionSecretPolicy`). `GET /v1/projects/{idOrName}/env/{id}`
returns a `value` for decryptable variables (Config and legacy `encrypted`). Consequence for this plan
(`docs/designs/BATCH-E.md` E1): **no tool returns any environment variable value, whatever its type**, because the
legacy `encrypted` type holds most real secrets in existing projects (Appliance Desk's Stripe and database keys among
them) and `visibility` is missing on legacy rows.

### 1.4 Things the API does not do (dashboard-only → guided settings, contract §11)

Confirmed absent from the reference on 2026-10-10: plan upgrade/downgrade and payment method; invoices as documents
(only FOCUS charge lines); **Spend Management** (on-demand budget, pause production, spend webhook — configured under
Settings → Billing, Pro and Enterprise); notification preferences ("My Notifications"); two-step login and passkeys;
deploy hooks (the CLI has `vercel deploy-hooks`, the REST reference has no operation); cron jobs: enable/disable and
"run now" (the CLI `vercel crons run` exists, beta; cron definitions are readable from the project/deployment);
**production branch tracking** (Settings → Environments → Production → Branch Tracking); connecting or disconnecting a
Git repository on an existing project (create-time `gitRepository` only); audit log export (Enterprise; now delivered
through Audit Log Drains since 2026-06-30 — a drain type, readable via the Drains API); SAML connection setup with the
identity provider (only `saml.enforced` and role mappings are API fields); team deletion and account deletion (API
exists; this plan never automates them — steps only); certificate upload (API takes a private key — never through chat).

## 4. Credentials (playbook step 4)

| Type | Scope | Fits? |
|---|---|---|
| **Access token, Full Account** | personal account and every team | Too wide. Refused by default (IN-04) |
| **Access token, Team** (`vcp_…`, chosen expiry) | one team, all its projects; reads and writes everything the creating member's role allows | **Recommended** for owner and operator connections: team settings, members, billing reads and domains are team-level, which a project token cannot reach |
| **Access token, Project** (added 2026-07-30) | one project; "requests to any other project, a user-level resource, or a team-level resource will be denied" | **Recommended in addition** for narrow connections (a pass for one app's agent, the scratch test project). Cannot mint tokens |
| Integration (OAuth) tokens | per installed integration with its permissions | Built for distributing integrations; not needed for Chris's own server |
| Sign in with Vercel access tokens with **per-resource permissions** (e.g. "Production Environment Variables — Read Only" vs "Non-Production … — Read and Write") | team and project permissions | The narrowest model Vercel has, but API permissions are **"currently in private beta"** (page dated 2026-02-26). ROADMAP: switch when generally available |
| OIDC tokens (`VERCEL_OIDC_TOKEN`) | a deployment's identity toward other clouds | Not an API credential for this server |

A token can do no more than the member who created it. Recommendation to Chris (IN-04): one **team-scoped token per
team** with a **90-day expiry**, created by a member with the Owner role (needed for team settings and members), plus
optional **project-scoped tokens** added as separate "accounts" for narrow connections. `vercel_whoami` and
`vercel_admin_overview` warn 14 days before expiry. Tokens are entered only on the setup page, stored AES-256-GCM
encrypted, never returned. The setup page probes the token (`GET /v2/user`, `GET /v2/teams`, `GET /v10/projects?limit=1`)
to record its scope; a token whose scope is Full Account is refused unless Chris ticks "allow full-account token" (IN-04).

## 5. Testing options (playbook step 5)

- **No Vercel test mode or sandbox account exists**; every API call acts on a real team. A free Hobby account is
  personal-only (no team features).
- **`emulate` by Vercel Labs** (`npm emulate`, version 0.12.1, Apache-2.0, repository `vercel-labs/emulate`, last
  published 2026-10-02): "local drop-in replacement services for CI and no-network sandboxes" — a stateful in-memory
  emulation of user/teams, projects (`/v9`–`/v11`), deployments (`/v13`, `/v6`, cancel, events, files, `/v2/files`),
  project domains and verification, env vars (`/v10`), protection bypass, Blob and OAuth. Pre-1.0 and partial, so it is a
  **second** test layer for the core areas, never the authority.
- **Decision (A-1, A-4):** three layers. (1) Unit tests with an in-process `fake-vercel` that records every request;
  (2) **request-shape tests** validating every recorded request (operation exists; path, query and body valid) against
  the vendored OpenAPI snapshot; (3) `emulate` tests (`npm run test:emulate`) for projects, deployments, env vars,
  domains and teams. Database code on throwaway localhost Postgres. A **read-only smoke test against Chris's real team**

## 6. Service-specific danger (playbook step 6) → guards

| What can hurt Chris | Guard |
|---|---|
| A production deploy, promote, rollback, rolling-release step, alias of a production domain | Production guard (B-2): production mode only, `confirm`, read-back, change log; previews do not need confirm |
| Production env var change (an app reads it at its next build or cold start) | Production guard; values never echoed; secret-shaped plain values refused (B5) |
| DNS change (breaks the site **and email** — Appliance Desk's Google Workspace mail and Resend records live on Vercel DNS) | Every DNS and nameserver write is production; MX/TXT records owned by a profile need `outsideApp` |
| Domain removal, certificate removal, firewall/WAF changes, attack mode, deployment protection changes, protection bypass secrets | Production guard; bypass secrets and access-widening protection changes are also access guard |
| Project deletion, transfer, pause (takes a live site down), Git connection change | Destructive + production; pause has an inverse (unpause) |
| Cron jobs (production-only by nature) | Read tools; enable/disable/run are guided (no API) |
| Buying: domains (purchase, renewal, transfer-in, auto-renew), credits, Marketplace stores with paid plans, Blob stores, analytics add-ons, drains (billed per GB), rolling releases, build machines/concurrency, sandboxes, seats (paid member roles) | Spend guard (B-1): always `confirm`, dollar preview where Vercel states the price (registrar; seat price setting), daily spend limit (default **$0**, IN-08); implementers never buy (AGENTS hard limit) |
| Inviting members, changing roles, access groups, trusted IPs off, Vercel Authentication off, shareable links, system bypass | Access guard: always `confirm` |
| Revoking the token this server runs on; changing this server's own project or the other Robinson servers' projects | Self-protection (B-3): refused unless Chris edits the protected-resources setting on the setup page |
| An app's own release process (Appliance Desk releases by moving its `live` branch) | Project profile (P): promote refused without `outsideApp`; emergency rollback allowed with confirm and labelled |
| Rolling back across a database migration (Appliance Desk runs `prisma migrate deploy` during every build) | Profile flag `rollback_caution`: the rollback preview names the risk and the migration check |

### SDK vs reference (why the plan uses a thin client)

`@vercel/sdk` 1.28.43 generates 435 operations; the reference lists 438. Present in the reference but missing from the
SDK: FOCUS billing charges and contract commitments, sandbox creation (`POST /v2|v3|v4/sandboxes`) and command
execution (`POST /v2/sandboxes/sessions/{id}/cmd`), sandbox fork/update, Vercel CI repository settings, Connect
authorize/token. Present in the SDK but gone from the reference: Checks v1 and the old log-drain operations. The
package is 55 MB unpacked and republished almost daily. Decision recorded in `docs/designs/BATCH-A.md` A7.
