# X-1 — Undo (Batch X)

Design: `docs/designs/BATCH-X.md` §1 (X1) + its 2026-10-27 amendment.
Dossier: `batch-w-dossier-2026-10-30.md` §5 (X-1 annex).
Precedent: Batch P verdict C-1 (composition through the dispatch seam).

## Scope

**(a) Inverse capture** for the §X1 clean-opposite families still
missing it (re-audited at this card's base, registry 239: only the
dns, firewall, routes/redirects, registrar (descriptive) and
globalconfig-schema families stored inverses):

- `vercel_project_pause` ↔ `vercel_project_unpause` (factory inverse).
- `vercel_deploy_promote` / `vercel_deploy_rollback` → rollback to the
  recorded previous deployment (`before.current`), with the change's
  own target as `expectedCurrent`.
- `vercel_alias_assign` → assign back to the recorded previous
  deployment.
- `vercel_env_set` create → `vercel_env_delete` of the created row
  (identity + revision read back at journal time); update →
  descriptive inverse carrying the design's sentence (a changed value
  cannot be restored). `vercel_env_copy` → delete of the created
  destination row, same pattern.
- Protection: `vercel_protection_set_vercel_auth` → re-apply the
  recorded previous scope; `vercel_protection_set_trusted_ips` →
  re-apply the recorded previous configuration (its `before` gains
  the current-value capture); `vercel_protection_set_password` →
  descriptive (the previous password is a secret this server never
  stores); `vercel_protection_create_bypass` → revoke the created
  secret, identified by note + creation time read back at journal
  time.
- `vercel_member_update_role` → restore the recorded previous team
  role (role changes only; a permissions/project-roles change
  stores a descriptive note — the previous permissions are not
  captured by that tool's `before`).
- `vercel_globalconfig_patch_items` → restore the recorded previous
  item values (its `before` gains the previous-values capture;
  revision read back at journal time).
- DNS + registrar + cert: the existing descriptive inverses gain a
  dispatch form (`vercel_dns_create_record` ↔ delete, update ↔
  restore, delete ↔ re-create from `before`, replace-zone ↔ restore,
  `vercel_cert_remove` → re-issue, registrar auto-renew and
  nameserver restores).

**(b) `vercel_undo_change`** (guarded write, C, everyday+full) in
`src/tools/undo.js`, description `{change_id, outsideApp?}`: loads
the caller's own change-log row through a new account-scoped db read
(`getChangeForUndo`), and dispatches the stored inverse through the
owning tool's own guarded pipeline with preview + confirm. An undo
journals as its own change-log row; the original is never rewritten.

## Verdicts recorded on this card

- **X1-C1 (dispatch form + the one adapter):** a dispatchable inverse
  is `{tool, ...args}` — the firewall/routes convention. The storage
  shaper hides any field literally named `value` in stored copies
  (the DNS family's `recordValue` lesson), so value-carrying
  dispatches cannot be stored flat: when dispatching, the undo tool
  translates `recordValue` → `value` and expands the DNS `record` /
  `restore` images into arguments. That translation is the undo
  tool's only adapter, and it is documented here.
- **X1-C2 (refusals name the opposite action):** rows with no stored
  inverse refuse by family: deletions name their re-create route,
  purchases/renewals/transfers say they are not undoable and name
  the dashboard/support route, invitations name
  `vercel_member_revoke_invite`, workflow rows (whose inverses are
  per-step pointers) name the step rows to undo individually, and
  descriptive inverses refuse carrying their stored sentence.
- **X1-C3 (undo of an undo):** the undo's own inverse is
  `{tool: 'vercel_undo_change', description: {change_id: <the
  dispatched step's own change-row id>}}` (the target tool's real
  argument shape), read back after the step lands — undoing an undo
  therefore re-dispatches the step row's inverse, which is the
  original change's opposite. No recursion special case exists.
- **X1-C4 (already undone):** `before` refuses a row an earlier
  confirmed undo already points at (found through the undo rows'
  journaled `undoes`), naming that undo's row id. Preview rows
  (`dry_run`) refuse: nothing was changed.
