# V-6 — Configurable Sandbox sizing and network (UA-08)

Status: implemented in this PR. Batch V card closing UA-08 (`docs/PRODUCT-AUTHORITY-AUDIT.md`): the V-4 Sandbox's fixed 1-vCPU/2-GB shape and deny-all network were the finite shape the 2026-10-17 scoped metered approval was granted against, hardened into a product limit. Design: `docs/designs/BATCH-V.md` 2026-10-30 amendment; tail dossier §4, 2026-10-30.

## Scope

- **Same operation, no new tool**: `vercel_dev_sandbox_create` gains optional `vcpus`, `network` and `allowedDomains` arguments. The catalog stays 240 registered tools; the front door is untouched.
- **Sizing**: `vcpus` ∈ {1, 2, 4, 6, 8} (the provider's rule is 1 or an even number; 8 is the product's supported ceiling). Memory is derived, never separately requested: the pinned contract requires `memory = vcpus * 2048`, so 1 vCPU = 2 GB through 8 vCPUs = 16 GB. Omitted ⇒ 1 vCPU / 2 GB, the historical shape.
- **Network**: `network` ∈ {`deny-all` (default), `allow-all`, `custom`}. `allowedDomains` (1–20 wildcard-capable patterns) is required with `custom` and refused with any other mode — never silently dropped. CIDR lists are a named future extension; the argument does not exist, so nothing is silently ignored.
- **Consent and metering unchanged in kind**: the preview and the metered spend declaration state the exact size and network in plain words; the operation's one-use grant is payload-bound, so owner consent covers exactly the requested shape. Minutes metering, atomic usage recording (`recordDevSandboxMinutes`), non-persistence, run ownership, preview-only profile enforcement and the run-object ledger are untouched; the ledger's session detail now also records the requested vcpus/memory/network.
- **Byte-identical default**: with all three arguments omitted, the provider body equals today's exactly (`resources:{vcpus:1,memory:2048}`, `networkPolicy:{mode:'deny-all'}`, `persistent:false`, same timeout/tags/source handling).

## Drift check A

| Assumption | Evidence | Resolution |
|---|---|---|
| The provider couples memory to CPU | Vendored snapshot `POST /v4/sandboxes`: `resources.memory` "Must equal vcpus * 2048"; `vcpus` "Must be 1, or an even number" | One `vcpus` argument; memory derived. Asking for memory independently would be a contract violation, not a feature |
| Network policy supports more than deny/allow | Same snapshot: modes `deny-all`, `allow-all`, `custom`, `default-allow`, `default-deny`; `custom` carries `allowedDomains`/`allowedCIDRs`/`deniedCIDRs` | Ship deny-all/allow-all/custom-with-domains; `default-*` modes are provider snapshot semantics with no caller need stated; CIDRs recorded as future, not built speculatively |
| Enlarging the shape breaks the V-4 metered consent | The grant is payload-bound and the spend declaration is generated from the bound shape | Preview/spend text is generated from the chosen shape, so the consented text is the executed shape; sizes change the metered rate, never the consent model |
| The session read-back can verify size/network | The pinned v2 session fixture carries identity/project/status only (`rowIdentity`) | Verify stays identity/status-based, as in V-4; the requested shape is recorded in the run ledger at creation instead of pretending a provider read-back exists |

## Verification

Fake-provider tests only; no live Sandbox is created. Verified locally on this VM (unit via vitest directly), then by exact-head CI.

- **Unit — shape normalizer** (`tests/unit/dev-sandbox.test.js`, extended): omitted arguments produce the historical shape; every supported size maps to `memory = vcpus * 2048`; odd sizes (3, 5, 7), 0, 10, non-integers and non-numbers refuse; `allow-all` and `custom` map to the exact provider `networkPolicy`; `custom` without domains, domains with a non-custom mode, empty/oversized domain lists and malformed patterns refuse; duplicate domains are deduped and sorted so the consented payload is canonical.
- **Unit — provider bodies** (same file): the exported pure body builder reproduces today's default body exactly, emits `{vcpus:4, memory:8192}` and the custom network policy for a sized request, and every emitted body passes the vendored OpenAPI request validation (`validateRequest('sandbox_create', …)`), extending the existing pinned-contract test rather than replacing it.
- **Unit — registry surface** (same file): the create tool's input schema carries the three new optional arguments with the declared bounds, and the tool description names sizing and network choice (still ≤160 characters).
- **Regression**: the V-4/V-5 suites (dev-sandbox, dev-sandbox-metered-approval, dev-v4-v5-doors/receipts/ledger, dev-preview, dev-runs) pass unchanged — the metered-approval behavior is untouched because the executor and preflight seams are not modified.
