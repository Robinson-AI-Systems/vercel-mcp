Status: IN_PROGRESS, candidate PR #174. Approved design: docs/designs/BATCH-E.md. Dependency: D-1 implemented; this read-only slice does not depend on incomplete D-3 writes. Baseline: 9f9be99d8baf2c9d20fc7fb50fa844a0f58e4684.
Budget: no paid provider calls or writes; no schema migrations.

## Current substantive slice: three native read capabilities

`vercel_env_list`, `vercel_env_get`, `vercel_env_export_names` resolve an exact server-selected project from the saved encrypted account, independently read `projects_get`, then use documented pinned GET `/v10/projects/{idOrName}/env` and GET `/v1/projects/{idOrName}/env/{id}`. The list always sends `decrypt=false`; get may receive provider fields but returns an allowlisted metadata projection only. All paths strip values of *every* type (plain, encrypted, sensitive, secret or system), including untrusted comment and metadata fields. No generic full-detail bypass, handles containing values, audit output or direct source dump. A metadata-only `.env.example` key export must contain assignments without values.

A returned variable with contradictory project ID, malformed key or ID, duplicate IDs/keys or unsafe field type fails closed. Pagination must describe boundedness honestly and never claim the complete provider inventory without a trustworthy cursor. Keys and targets are bounded/sanitized. No cross-project/team requests.

## E-1 drift comparison (#177 candidate)

`vercel_env_compare` completes an independently usable read-only comparison for up to 20 explicitly named keys and two exact project/target selectors. Only provider-verified Config rows with values available from scoped GET are compared via ephemeral SHA-256; no value, digest or size leaves memory. Secret kinds return `cannot_compare_secret`; absent keys on unverifiable provider pages return `inventory_unverified`, not a fabricated absence; changed identity fails closed. Read-only operation; no producer write, production change or spend. Automated fake-provider validation and exact-head CI required; genuine hosted custom-service acceptance remains separate. The five mutating/copy operations are not covered by this PR.
