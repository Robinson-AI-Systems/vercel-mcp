## What this card builds

One read tool, `vercel_workflow_app_readiness` (all profiles), that checks
every row of a stored profile (`{app}`) or an inline `{spec}` and returns one
verdict per row: `done` / `fixable` / `needs_you` / `needs_decision`, with a
summary count. Rows: project exists; framework; Node version; production
branch; expected variable names per target (missing names produce
pending-input requests — values are never invented or read); managed variable
presence (a missing managed name is `needs_you`: connect the integration,
never set it by hand); preview database isolation via `vercel_env_compare`;
crons vs `expected_crons`; owned domains attached + verified; owned DNS
records present; owned stores connected; preview protection; guided
`dashboard_settings` rows (enriched with `vercel_where_is_setting`); the
release-rule row (informational). Composition is read-only through the
registry `dispatchTool` seam — guards and profile gates apply exactly once,
inside the area tools.

| R-2 | Node version mismatch → confirmed fix | `vercel_project_update_settings` exposes commands/directories/name/framework only — no area tool changes a project's Node version | Node mismatch is `needs_you` (engines in `package.json`, or the dashboard's Node.js Version setting, with read-back) |
| R-3 | Preview DB isolation via `vercel_env_compare` | Compare reports `cannot_compare_secret` for Secret-kind keys — `DATABASE_URL`/`DIRECT_URL` are secrets, so sameness is unprovable by design | Row dispatches compare and reports its verdict verbatim: `different` → done; `same` → needs_you (not isolated); anything else → needs_you (unverifiable without reading values, which this server never does) |
| R-4 | Domain renewal/auto-renew row (APP-NEEDS V13) | `vercel_domain_list`'s summary carries `expiresAt` but no auto-renew field | The domain row reports expiry; no auto-renew verdict is invented |
| R-5 | "missing preview bypass" may-fix | No P2 profile field expresses a bypass expectation (APP-NEEDS V16: "Not used today") | No bypass row until a profile field exists |

## Build-time findings (fixture vs contract)

- Profile DNS rules write the apex name as `@`; provider DNS records
  report it as `''`. The readiness matcher normalizes both before
  glob-matching, or the MX/SPF apex rules can never match.
- `PREVIEW_PRIVATE_BLOB_READ_WRITE_TOKEN` is one of the profile's
  managed names (the preview private store's platform token): a missing
  one yields the connect-the-integration step, not a pending input. The
  pending-input acceptance case uses a plain name (`RESEND_API_KEY`).
