## Implementation
- `visibleToProfile` requires explicit per-tool metadata, fails closed when profile or writes declaration missing and hides every write from read_only.
- `listProfileTools` removes private metadata; `profileToolCounts` derives counts from the same access predicate.
- MCP discovery, direct tool invocation and the home page share identical eligibility rules.
- `tests/unit/profiles.test.js`: direct-by-name read-only refusal, explicit local owner allowed on full only, reject undeclared/arbitrary writes, scrub listing metadata, counts equal eligible tools.
- Test commands: `npm run check`, `npm test` and five exact-head CI jobs (check, unit, db, emulate, aggregate ci).
- No owner input needed. Never enlarge the local owner allowlist or change protected-resource defaults without explicit approval.
