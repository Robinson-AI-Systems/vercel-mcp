## What this card builds

- **`known_apps` (additive table, schema pin 18 → 19)** — design §2 plus
  two columns the repo's account model requires (dossier S-6/S-7):
  `vercel_account` (the internal account scope, NULL = every account,
  the `protected_resources` semantics) and `source` (`default` seed /
  `setup_page` / `draft`). Accessors `listKnownApps`, `getKnownApp`,
  `upsertKnownApp` on `src/db.js`.
- **The Appliance Desk seed**, generated from
  `docs/APP-NEEDS-APPLIANCE-DESK.md` as re-verified against the live app
  repo on 2026-10-30 (dossier §2). Seeded from `initSchema()` with an
  upsert that refreshes the row only while its source is `default`, so
  the APP-NEEDS rule "file and seed change in the same PR" actually
  deploys and owner edits are never overwritten. Exported as
  `KNOWN_APP_SEED` for tests.
- **The real profile guard** (`src/tools/app-guard.js`, replacing the
  B-7 constant-allow stub): pure matcher `checkAppTargets` + async
  `checkApp` mirroring `checkProtected` (fails closed when profile data
  is unavailable; an account with no profiles allows). Rules, each
  naming the owning app: managed env keys; owned stores (by connection
  label, by `storeName` target field, or by setup-page store id);
  owned DNS records (design-N5-style type/name/value-prefix rules on an
  owned domain or owned project); protected sandboxes by name;
  branch-release-rule actions (promote, rolling start, production
  deploy) without an `outsideApp` marker. Rollback is never blocked.
- **Target enrichments (additive fields only)** so the guard can see
  what the design asks it to judge (dossier S-1…S-4): env targets gain
  `key` + the `outsideApp` marker (env set/delete/batch/copy; the env
  write family gains the optional `outsideApp` argument its deference
  requires); Blob put/delete targets gain `storeName`, `storeAction`,
  `overwrite`, the marker; the Blob-store delete target gains the
  marker; release-write targets gain `release` + the marker on the
  project target; rolling-start targets gain `release: 'rolling_start'`
  + the marker; deploy-create targets gain `deployTarget` + the marker.
  `checkProtected` reads only its known fields — unaffected.
- **Rollback label** (design P2): when a promote/rollback preview's
  project carries an alias domain a profile owns, the preview names the
  app; rollback additionally carries the profile's `rollback_caution`
  and the design's emergency-rollback wording.
- **Profile-aware no-preview branches** (dossier S-10):
  `vercel_dev_preview_branch` / `vercel_dev_preview_env` now consult the
  account's profiles' `no_preview_branches` globs; with no profile data
  the legacy hardcoded rule remains as the built-in default.
- **Profile reads**: `vercel_profile_list`, `vercel_profile_get`
  (registry 181 → 183), and the `app` mark on `vercel_project_get` /
  `vercel_project_list` results for profile-owned projects (dossier
  S-8 records the narrowing: other reads gain the mark as the workflow
  tools that compose them land).
