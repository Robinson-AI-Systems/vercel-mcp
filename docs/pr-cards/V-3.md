## Complete acceptance and implementation boundaries

- `vercel_dev_tail_logs`: authenticated preview-only active owner/run/project/deployment, bounded build events or existing D-2 runtime stream, signed account/deployment/source cursor with one-hour expiry, forward-only new lines and explicit non-completeness. Reject foreign/expired/tampered cursors, unbounded provider arrays, malformed event identities and production connections *before any provider read*. Sanitize log content; never return raw secrets.
- `vercel_dev_diagnose_build`: locate first error in at most 250 pinned `deployments_events` rows; classify exactly the ten synthetic-tested scenarios in `src/dev/build-failures.js`, provide finite actionable non-spending fixes, redacted snippet and honest incomplete-evidence disposition; no automatic build.
- `vercel_dev_fetch_preview`: exact recorded active preview and only Vercel-attested *.vercel.app hostname, at most 10 normalized paths, server-private recorded encrypted bypass, no user-controlled URLs or query/fragment/redirect traversal, 3-second timeout, ≤4 KB response. Resolve all addresses and reject mixed/private/loopback ranges; **pin the verified public IP in the actual HTTPS connection** while preserving hostname TLS/SNI validation to defeat DNS rebinding. Never send bypass through redirect or output. Tests may inject a mock fetch adapter; native runtime must use pinned HTTPS.
- `vercel_dev_check_integration`: typed preview/development variable **names** only with decrypt=false, selected run-scoped preview aliases/domains, config-only cron state (not applicable as previews do not execute cron schedules), Node/framework/protection and tracked bypass metadata; third-party integration unsupported verification remains explicitly unverified. Incomplete inventory never earns READY; refuse production environment requirements and any claim of activated production functionality.
