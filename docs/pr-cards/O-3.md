## Drift check A
| Assumption | Evidence | Resolution |
|---|---|---|
| Tool-created tokens need new storage machinery | `storeToken` already probes, encrypts and upserts accounts; AUD-K2/AI enrollment uses it | The 'server' delivery route composes with `storeToken` (`allowFull:false` enforces the never-full-account rule); no new storage |
| Enrollment records token expiry | All three store sites wrote `expiresAt: null` unconditionally — VMCP-003's recording gap | `storeToken` gains an additive optional `expiresAt` param (default null; existing callers byte-identical); the tool passes the created expiry through. The personal/installation store sites are untouched |
| The create response can return through the write result | client.js `safeReplayResult` screens the replay-bound result for sensitive field names and credential-shaped values | The bearer is captured in the apply closure via `shapeResult` and leaves only through the one-time reveal or `storeToken`; the result carries metadata + `ownerRevealRef` only |
| token_delete can recognize the server's own token | vercel_accounts has no provider token-id column | Two-layer guard: exact provider-id match from the account probe (tokens this server creates record `providerTokenId`), then the documented `suffix` against the account row's stored last-4 — fail-safe toward refusal, dashboard route named in the refusal |
| Create takes teamId as a caller query | Client refuses caller team overrides on unscoped ops; the endpoint's teamId is a documented QUERY param | The operation stays team-scoped so the client attaches the STORED team's id itself; the caller never supplies it |

## Build
- `vercel_token_list` (read, all profiles): documented projection — name, type, prefix/suffix, scopes, created/expires/last-used, leaked and revoked flags; `expiresAt: null` reported as "no expiry reported", never upgraded to an attestation.
- `vercel_token_create` (guarded write, C A, `secretOut` + one-time delivery): scope team|project only; expiry is the creator's optional choice (IN-04); delivery `reveal` (one-time secret on the setup page) or `server` (stored directly as another account of this server via the existing probe, recording `providerTokenId` provenance and the expiry — the tool-created leg of VMCP-003's gap).
- `vercel_token_delete` (guarded write, D C): refuses the connection's own credential (exact provider-id, then suffix), refuses unreadable targets; verification is the post-delete read failing.

Tests: tests/unit/tokens.test.js (7) incl. a no-bearer-anywhere assertion over plan + applied results and both self-guard layers. Fake provider only; no live token call. Verification on the Workshop bench (chris-agent-01, node:24 container) — see the PR body.
