### Exact OpenAPI parser drift reconciliation (#49)
The vendored Git search query includes an invalid OpenAPI 3.0 `nullable` annotation without a `type`; vanilla Ajv fails compilation even for a safe non-null string. `normalizeNullableDeclarations` removes **only** untyped nullable annotations before Ajv compilation (including referenced components). It never removes enum/pattern/required/type constraints. Null is not silently admitted; malformed input still fails. Direct pinned-query and nested-schema tests catch regression.

The same pinned `git_repos_search.namespaceId` schema contains duplicated `oneOf` alternatives (`string,number,string,number`), which rejects every value under exact-one rules. Normalization deduplicates only structurally identical `oneOf` branches; it does not convert `oneOf` into `anyOf` or accept types outside the published union. Valid string namespace IDs now pass with the original query validator. Extra unit coverage pins this workaround to the vendored snapshot.

The existing Ajv query-string coercion is preserved for established Vercel operations (e.g. project page limit in the pinned schema is string-like). The only non-exclusive validation exception is the exact `git_repos_search:query:namespaceId` parameter: its duplicate `oneOf` type alternatives are deduplicated and interpreted as the documented union (`anyOf`) while retaining each member's type constraints. Unrelated `oneOf` remains exclusive; no general validation weakening.
