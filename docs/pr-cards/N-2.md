## Decisions carried from the dossier
- **Zone-first writes (N2).** Every DNS write reads the whole zone
  first (following the documented `next` timestamp cursor as `since`;
  an unprovable page refuses the write). Previews show the record
  before/after plus conflicts; inverses journal the restore (delete →
  re-create from the before-image; update/replace → prior zone).
- **Conflicts.** CNAME at a name holding any other record type (or any
  record at a name holding a CNAME), a second MX set at a name, and a
  duplicate SPF (`v=spf1`) TXT at a name are named in the preview;
  creating a CNAME over existing records refuses in `before` (the
  design's preview-check made executable: DNS itself forbids the
  coexistence, so the provider would corrupt or refuse).
- **Type shaping.** `dnsType(row) = row.recordType ?? (documented enum
  includes row.type ? row.type : null)` — updateRecord's 200 carries
  `type` as the record/record-sys discriminator, not the DNS type
  (dossier §3).
- **Dossier §4.1 (SRV/TXT branches unsatisfiable, corrected at build).**
  Both branches require `name` yet omit it from `properties` under
  additionalProperties:false — no documented body can validate (proven
  against the repo validator). A scoped exemption in
  openapi-validation.js skips body validation for those two record
  types only (F-2/F-3 precedent); bodies are pinned byte-exact in
  tests. Named TXT creates work like every other type.
- **Dossier §4.2 (replace_zone transport).** The documented PUT
  /domains/{domain}/records has NO request-body contract in the
  snapshot or the live reference/SDK, so the raw PUT is not called.
  `vercel_dns_replace_zone` replaces the whole set in one tool call by
  composing the documented create/update/delete endpoints; the preview
  lists every add, change and removal; verify re-reads the whole zone;
  partial application reports the actual end state, never success.
- **Dossier §4.3 (no issuer).** Cert summaries carry exactly the five
  documented fields (id, cns, autoRenew, createdAt, expiresAt); the
  catalog's "issuer" wording is amended by note.
