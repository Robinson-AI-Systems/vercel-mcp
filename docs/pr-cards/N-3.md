## Decisions carried from the dossier
- **Spend composes, never bypasses (§5).** Buy/renew/transfer declare
  `risk.spend` with `spend()` returning the fresh quote in integer
  cents (exact decimal conversion from the documented number|string
  prices; an unrepresentable price refuses the declaration). The
  executor's pre-dispatch re-run refuses any quote drift; apply sends
  `expectedPrice` in dollars, so the provider independently refuses a
  changed price with `expected_price_mismatch`. Classification per
  dossier §4.1 AS CORRECTED AT BUILD: apply re-quotes inside its
  pre-dispatch check and refuses drift before dispatch; a provider-side
  rejection surfaces its code in the result's failure detail (the
  executor reports post-claim apply failures as outcome_unknown, AUD-H). Owner-word
  connections disclose-and-execute (OP-2); delegated connections take
  the purchase-intent grant path whose fingerprint binds the quote.
  The registrar context wires the REAL `accountSpendGuard` (the
  universal.js composition), not a stub.
- **Registrant contact (§4.2 — deviation from the design's "stored as
  an account setting" wording, recorded).** No registrant store exists
  (no DB column, no setup form — grep-verified). Contact arrives as a
  NEW pending-input kind `registrar_contact`: the owner pastes the
  contact JSON once on the setup page; buy/renew/transfer take
  `contactInputId`, consumed inside apply, parsed and validated
  against the documented contact schema + `validateRequest` before
  dispatch. Contact values never appear in args, previews (field names
  only), audits or inverses. A persistent registrant setting is a
  flagged follow-up, not built here.
- **Transfer auth code (N5).** Transfer-IN consumes a
  `transfer_auth_code` pending input inside apply; any direct auth-code
  argument is refused by exact-args. Transfer-OUT (`get_auth_code`) is
  secretOut + oneTimeDelivery: the code is issued to the one-time page;
  results/audits/replay carry only the reveal reference.
- **Auto-renew (§4.4).** One write, dynamic `spend()`: ON →
  `{cents: null, recurring: true}` (the spend-table class); OFF →
  `{cents: 0, recurring: false}` through the $0 checkSpend path
  (confirm-only C behavior). The OFF preview warns the domain expires
  on its expiry date. No documented 200 body for either PATCH —
  state is proven by read-back through `domains_get`.
- **Search (§4.3).** The contract checks exact names (1–200); it does
  not generate suggestions. Catalog wording amended by note.
- **Prices are USD dollars** (guide + snapshot floor 0.01); the
  1125-cent guidance fixture renders "$11.25" in previews.
