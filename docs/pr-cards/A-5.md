## Build contract
- `src/vercel/tokens.js`: server-only AES-256-GCM encryption using TOKEN_ENCRYPTION_KEY; probe `GET /v2/user`, `GET /v2/teams`, `GET /v10/projects?limit=1` with pinned OPS entries; team/project token scope; expiry; encrypted persistence via `src/db.js`; refuse account-wide token unless owner explicitly opts in through setup.
- `api/vercel/setup.js`: passphrase-protected, database-counted login throttling (reuse A-3); never render/echo token or another secret; add/manage connections and pending inputs; non-production deployments refuse production enable.
- `src/core/one-time-secrets.js` and `src/core/pending-inputs.js`: encrypt, persist, single-use retrieval and deletion with expiry. The setup page is the only secret entry or exit.
- `src/tools/server.js`: `vercel_whoami` and `vercel_list_accounts`, read-only, no secret output, matched to TOOL-CATALOG and existing registry.
- Add only schema/operation entries verified in pinned JSON. Never use a live Vercel token to test.

## Tests and acceptance
- Unit and disposable-Postgres: ciphertext never equals submitted fake token; missing/bad key fail closed; encrypted round-trip; one-time secrets shown once; pending inputs consumed once; token scopes accurately classified; full-account blocked by default.

- HTTP setup page: passphrase lockout at 5 attempts in 15 minutes, no token reflection, production switch inaccessible in preview.
