## Build contract

| File | What |
|---|---|
| `src/db.js` | The **only** file with SQL. `import { neon } from '@neondatabase/serverless'`. Exports: `SCHEMA_TABLES` (frozen, the nine names below); `CONNECTION_FIELDS = ['vercel_account', 'mode', 'profile', 'listing']` and `connectionSettings(row)` (A-3's refresh copies exactly these); `createDb(sql?)` → `{ initSchema() }` where `sql` is a Neon-shaped tagged-template function (tests pass `neonShapedQuery()`), defaulting lazily to `neon(process.env.DATABASE_URL)`; a missing `DATABASE_URL` throws `DATABASE_URL is not configured…` only when a query is made, never at import; `initSchema()` (module-level) = `createDb().initSchema()` |
| `initSchema()` body | Exactly BATCH-A §2: `vercel_accounts`, `oauth_clients`, `oauth_codes`, `oauth_tokens`, `login_attempts`, `change_log`, `one_time_secrets`, `pending_inputs`, `protected_resources`, all `CREATE TABLE IF NOT EXISTS`; indexes `IF NOT EXISTS`: `change_log_request_key (request_key, at)` (§2), plus `oauth_codes (expires_at)`, `oauth_tokens (refresh_hash)`, `oauth_tokens (expires_at)`, `login_attempts (ip, attempted_at)`, `change_log (vercel_account, at DESC)`, `one_time_secrets (expires_at)`, `pending_inputs (expires_at)`. No `DROP`, no `ALTER … DROP`, no data rows (the protected-resource seed is A-5) |
| `test/helpers/fake-db.js` | Keep `put/get`; add `initSchema()` recording `SCHEMA_TABLES` and `listTables()` so unit tests can assert idempotence; first-line comment updated |

Defaults that matter for safety (assert them): `vercel_accounts.production_enabled` FALSE, `spend_limit_cents` 0
(IN-08), `sandbox_minutes_per_day` 60 (IN-13), `scope` NOT NULL; `oauth_codes`/`oauth_tokens` `mode` default
`'preview'`, `profile` `'everyday'`, `listing` `'catalog'`, `kind` `'connector'`; `change_log.production` FALSE;
`protected_resources.source` `'default'` and `UNIQUE (vercel_account, kind, match)`. Token columns are hashes or
ciphertext only (`token_hash`, `refresh_hash`, `token_enc`, `ciphertext`) — no plain-token column anywhere.

Note for the reviewer: `UNIQUE (vercel_account, kind, match)` treats two NULL `vercel_account` rows as distinct (the
Postgres default). Use `UNIQUE NULLS NOT DISTINCT` (Postgres 15+; CI runs 17) so an "every account" default cannot be inserted twice —
record it as a dated BATCH-A amendment in the PR and add "Neon database on Postgres 15 or newer" to A-6's DEPLOY.md
notes (`docs/designs/CHANGES-SINCE-DESIGN.md`).

## Tests

- `tests/db/schema.test.js` (throwaway Postgres via `npm run test:db`): the nine tables exist and nothing else;
  `initSchema()` twice changes nothing (same tables, same columns, same indexes); every default listed above; no column
  named like a plain token (`access_token`, `refresh_token`, `token`, `value`, `plaintext`); inserting the same
  `(NULL, 'project', 'vercel-mcp')` protected resource twice fails with a unique violation, and per-account duplicates
  fail too; `change_log_request_key` index exists.
- `tests/unit/schema.test.js`: `createDb()` with a non-function throws; importing `src/db.js` with no `DATABASE_URL`
  does not throw; the fake's `initSchema()` is idempotent and lists `SCHEMA_TABLES`; `CONNECTION_FIELDS` is exactly
  the four connection columns.
- `tests/unit/db-contract.test.js` and `tests/db/contract.test.js` still pass unchanged.
