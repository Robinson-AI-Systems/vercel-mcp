## Drift check A
| Assumption | Existing code at B-8 | Correction |
|---|---|---|
| Result owner is a stable connector ID | `requireMcpToken` returns account/clientId/mode/profile/listing, not unique bearer identity | Derive stable secret-safe server-side identity after bearer authentication; never trust args |
| 8 KB output has durable overflow | `compact` throws beyond 8 KB | Redact, project/summary, then persist sanitized full data in SQL and issue opaque scoped handle |
| Every read supports fields/detail | Current handlers do not | Central registry/dispatch injection; do not hand-edit every area |
| Result store exists | No result_store table | Add additive SQL with 24h expiry and capped cleanup |

## Build contract
1. Validate SDK annotations/structuredContent against pinned installed version before modifying discovery.
2. Design and test stable **per-connection/pass** owner identity without returning bearer hashes in MCP/DB output.
3. Add `src/core/result-rules.js` for allowlisted field projection, summary/full and result splitting, redaction *before* persistence; `src/tools/summaries.js` for 6–12 safe fields per object.
4. Add `result_store` in `src/db.js` with opaque `res_` handle, indexed expiry, owner scope and cleanup of at most 100 expired rows per access. DB APIs enforce ownership server-side.
5. Register `vercel_get_result({handle,page?,fields?})` read-only across profiles; no caller-supplied account/owner.
6. MCP dispatcher injects view settings and presentation without bypassing B-8 authorization; annotate tools. No Vercel API writes.
7. Update catalog, architecture, index, STATUS, owner guide, design drift notes and regression fixtures as-if merged.

## Concrete fixtures and acceptance
- 100 deployments including nested fake credential-shaped values; summary under 8 KB, counts and stable pagination; >8 KB sanitized full body stored 24h, safe preview with handle and record count.
- Two OAuth connectors sharing account/client ID: A's handle denied for B; expired/unknown and tampered handles denied. Concurrent cleanup deletes ≤100 rows.
- Environment summary and full view never reveal `value`, encrypted fields, bearer, password or webhook secret.
- `fields` exact dotted-path projection, malformed/unknown path reported safely; `detail=summary|full` only, never an uncontrolled provider query.
- Existing direct MCP write denials, owner approval-only references, read-only/everyday/full visibility remain intact.
- Fail on DB missing, unknown ownership, unsafe output, oversize or invalid schema; no silent truncation, provider writes or new production access.

## C-1a — foundational storage and ownership (#41)
- Authenticated bearer gets nonenumerable per-token `resultOwner` (not client ID); no result owner leaks into serialized connection or audit.
- `createDb.putResult/getResult` provide owner+account isolated 24-hour max handles, up to 1 MiB redaction-before-persistence and bounded 100-row expiry pruning; do not expose unwrapped SQL through MCP.
- Unit bearer identity and disposable Postgres result-store/schema checks; next #42 field/detail/summaries, then #43 tool and annotation integration.

## C-1b — summary and field projection rules (#42)
- `src/tools/summaries.js` supplies allowlisted safe project/deployment/env/domain/member/token/etc summaries; `src/core/result-rules.js` validates up to 20 dotted paths, reports unknown fields, removes every secret value key even under full detail, sanitizes nested credentials, and caps source at 1 MiB.
- Unit matrix of 100 env rows, full vs summary, webhook host and deployment commits, unknown/prototype paths and oversized values; #43 wires this into real MCP tools and 8 KB handle storage.

- Architecture regression caught by GitHub Actions: provider-specific mapper now injected into provider-neutral result core; core import gate remains enforced. (#42 correction)

## C-1c — bounded MCP delivery and result retrieval (#43)
- On the real API MCP door, large sanitized read responses now issue scoped 24h handles and a small human preview; no overflow is silently truncated. An exact-bearer-bound read-only `vercel_get_result` returns pages of 20 and refuses foreign/forged/expired handles, invalid page or unbounded page output.
- Generic read input schemas advertise `fields/detail` and safe annotations; handlers never forward presentation selectors to a Vercel operation. Existing guarded writes stay unchanged and unlisted outside full. Structured output remains reserved for future workflow tools (none shipped yet).
- Unit `tests/unit/result-delivery.test.js` covers 100-row oversized result, tenant/bearer isolation, paging, projection, and profile visibility; isolated SQL result-store test #41 covers expiry and ownership. Next: C-2.
