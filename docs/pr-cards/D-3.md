## Scope and architecture

Implement in independently verified risk-coherent slices without weakening global production, cost, protected-resource or replay guards. This first slice implements **preview cancellation only**; the remaining four names must not be marked built yet.

Existing interfaces: `src/tools/deployments.js` `scopedDeployment` verifies returned provider deployment ID/project against the stored team/project credential; `src/vercel/provider.js` `writeProvider` binds durable transport replay; `src/core/write.js` `defineWrite` handles confirmation, target, production, audit, owner guards and independent after-state verification.

## PR #172 behavior

- Implement `vercel_deploy_cancel` with required exact `deployment`, optional exact `project`, `dryRun`, `confirm` and replay `requestKey`. No caller team/token override.
- Pinned provider mapping: GET `/v13/deployments/{idOrUrl}` before, again immediately before apply and after; PATCH `/v12/deployments/{id}/cancel` only after the guards succeed. Query team is from encrypted stored connection, never caller.
- A cancellation target must be definitively a preview (`target: preview` or explicitly `null`) and currently QUEUED, INITIALIZING, or BUILDING. Unknown target, production, READY, ERROR, CANCELED, inconsistent IDs/ownership/state, protected deployments and app-owned projects all refuse before PATCH.
- Only guarded `full` or `everyday` profile; preview connection permitted, production changes never executed. No money declaration: cancelling a build does not create usage; no external provider mutations in acceptance tests.
- Dry-run and no-confirm make no PATCH; execution rechecks exact identity, project, target and state before PATCH and reports `confirmed:true` only on independently observed CANCELED. Replays cannot repeat PATCH.
- All provider response content is shaped; no raw events or secret values.

## D-3b (#175 candidate): irreversible terminal preview cleanup

Add `vercel_deploy_delete` for explicit `CANCELED` or `ERROR` previews only, with required exact deployment/project ID, expected terminal state and `outsideApp:true`. Production-targeted, READY, running, unknown target, alias-bearing, alias-unknown, changed scope/state/identity, and protected deployment/project cases refuse before DELETE. Absence of Vercel alias information is **not** proof of safe cleanup. The existing guarded-write contract supplies confirmation, audited previews, durable replay, protected/app checks and strong original profile gate. PINNED provider mapping GET `/v13/deployments/{idOrUrl}` → immediate re-read → DELETE `/v13/deployments/{id}` → independent GET. Only a verified 404 from the same stored team/project credential is positive deletion evidence; HTTP errors remain unknown, a still-present deployment is unconfirmed. No GET, delete or replay result leaks provider metadata.

Automated acceptance: `tests/unit/deployment-delete.test.js` covers exact request mapping, terminal positive and readback, no-confirm/dry-run, production and alias denial, all scope/identity/state races, protected targets, rotated project credential, empty/unknown provider responses and replay without a second DELETE. Required all-job GitHub Actions and release-policy checks; no real provider deletion or deployment release in this slice. Three D-3 creation/redeploy operations remain; metered operations stay disabled without owner-approved enforceable ceiling. Broader deletion is separately gated.

## D-3c — target-preserving redeploy with independent spending gate (candidate #191)

Pinned POST /v13/deployments with original `deploymentId`, project name and immutable `target`; verified source/project/state/target must match a separately supplied exact selector before any provider dispatch. Preview and production outcomes preserve source target; a preview-mode agent cannot redeploy production. Full-profile, explicit outside-app intent, protected resource, audited confirmation, durable replay, pre-dispatch state recheck, separate provider readback and independent consumed owner approval remain required. Each build incurs unbounded metered usage, so `risk.spend` declares an unbounded recurring cost and the existing central IN-08 gate refuses confirmed execution until Vercel can enforce an operation ceiling and the owner independently approves it. Offline requests/denials may be proven, but real redeploy acceptance is not authorized; do not call this a completed live capability or loosen spending. Next: other D-3 create-from-Git and file workflows under the same gate.

## D-3d — linked GitHub exact commit deployment (candidate #192)

The approved Git-source deployment path constructs pinned POST `/v13/deployments` from a stored-provider-verified linked GitHub project only, using an exact 40-hex Git SHA and validated branch ref supplied by the caller. An unlinked, foreign-team, renamed, rotated, mismatched Git/project or unsafe ref fails closed. Before a provider write, the project link and team are read again; selected preview/production target is explicit and protected/app checks, independent owner purchase approval, durable replay and created-deployment readback are required. IN-08 declares an unbounded recurring metered build charge, so all `confirm:true` calls refuse before POST until a provider-enforceable per-operation ceiling is available. This PR proves schema, catalog, fake-provider and denial paths—not a live build or cost approval. GitLab and Bitbucket remain outside this GitHub-only slice; separately approved files workflow is next.
