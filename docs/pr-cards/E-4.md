# E-4 — Global Config tokens and schema

Status: **IN_PROGRESS**. Approved scope: `docs/designs/BATCH-E.md`, the Global Config token/schema sections in `docs/TOOL-CATALOG.md`. Depends on E-3 source and guarded write foundations. E-3 native TEST acceptance is queued, not a blocker to adjacent token code.

## Token lifecycle source candidate

- `vercel_globalconfig_list_tokens` reads the exact team/store token inventory
  via pinned `GET /v1/global-config/{edgeConfigId}/tokens` and returns only
  ID, verified safe label and issuance date. Token strings, raw envelopes,
  decrypted values and provider secrets are never returned regardless of
  requested detail or caller profile. Bounded 20 items; incomplete views
  marked.
- `vercel_globalconfig_revoke_tokens` implements full-profile exact-ID
  targeted revoke by `DELETE /v1/global-config/{edgeConfigId}/tokens`
  with `{ids:[...]}`, selected-team and all linked-project proof, an
  explicitly version-checked store, complete token inventory, pre-dispatch
  recheck, protected/app guards, durable replay and independent absence proof.
  Any connected project classifies the change as production, so preview mode
  cannot silently break live consumers. Destruction requires confirmation.
- These read/revoke tools are implemented together with E-3's one-time
  token creation to deliver a working issuance, inspection and revocation
  lifecycle rather than isolated slivers.
- **E-4 schema scope:** implemented in a subsequent cohesive source candidate, with exact-head CI and genuine native provider acceptance still open.

## Schema lifecycle source candidate

- `vercel_globalconfig_get_schema`: exact provider store identity plus pinned
  `GET /v1/global-config/{edgeConfigId}/schema`; return bounded, credential-
  shaped-field-redacted JSON Schema or explicit provider 404 absence.
- `vercel_globalconfig_set_schema`: `mode:set` or `mode:remove`.
  Validate entire actual item map with offline AJV; dry-run reports named
  incompatible keys without raw values; confirmed incompatible set fails
  closed. Disallow external schema resolution, credential-bearing schema
  definitions, unknown owner/team/links, stale revision, protected/app resources,
  and preview writes to any live-connected project.
- `POST /v1/global-config/{id}/schema` sends only the bounded definition;
  `DELETE /v1/global-config/{id}/schema` removes under full profile.
  Both recheck original schema, revision and item inventory immediately before
  provider mutation, then read the actual schema again independently.
  The prior safe definition is logged as an inverse requiring a fresh revision
  (never an automatic replay).
- E-4 approved engineering code should be source-complete when this PR's
  full CI and merge pass. Native owner-approved TEST read/set/remove and
  subsequent cleanup must independently close its acceptance queue.
