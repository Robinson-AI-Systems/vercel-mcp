## Scope and full acceptance criteria

1. `vercel_dev_preview_branch`: exact existing Vercel project/GitHub repository, branch and SHA, current account/run, preview target only, no-preview patterns `ai/**`, `transfer/**`, `recovery/**` unless explicit `outsideApp`. A preview build is **metered** and cannot run until IN-08's provider-enforceable per-operation lifetime charge ceiling plus independently authenticated one-use owner grant. When permitted, record pre-dispatch run intent, exact returned deployment ID and preview metadata, read status up to 45 seconds and return pending/failed evidence honestly.
2. `vercel_dev_wire_preview_env`: exactly one of safe nonsecret inline value, owner-private pending input, generated value per named variable; 1–5 in one call; branch optional; `target:['preview']` always; no overwrite of an existing key/branch; full bounded env inventory and repeated no-duplicate checks, metadata-only result. No value/hash/plain secret in MCP result, audit, replay or run detail. Exact env IDs durable and deleted by V-1 cleanup only after current preview target and run-comment proof.
3. `vercel_dev_alias_preview`: run-namespaced `rtc-<run-id>-*.vercel.app` alias and exact **recorded** ready preview deployment; no production or traffic takeover. Independently prove alias absent before POST, and returned `oldDeploymentId` absent; record alias ID then verify authoritative routing. V-1 cleanup only removes same alias ID still pointing at same preview, with readback 404.
4. `vercel_dev_create_bypass`: Vercel protection automation bypass is project-wide: only a V-1 owned isolated scratch project with complete zero production/alias inventory can be eligible. Explicit owner confirmation and access widening classification. Cryptographically generated credential never enters MCP outputs; AES-GCM encrypted revocation material recorded before PATCH, one-time reference issued via authenticated setup route. V-1 cleanup revokes exact same credential only after independent provider proof; unknown effect remains unresolved rather than fabricating deletion.

All V-2 entry points refuse production connection **before** provider reads. Protected/self/app guard and actual selected connection authority apply at preflight and before each write. Stable keys, persisted run/object intents, last-known owned state, fail-closed partial/unverifiable outcomes and no blind retry. Source/deployed/provider acceptance remains distinct. No app profile is yet configured: common branch cost exclusion patterns are explicit, not a claim that live profile rules have been deployed.
