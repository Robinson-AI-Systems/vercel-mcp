## Build contract
- `src/tools/production-guard.js`: deny production mutation on preview connections, require `confirm` in production, show PRODUCTION banner, and never infer live status from absent data.
- Owner enable request `vercel_enable_production` is two-step: a confirmed, limited pending request plus owner passphrase reentry on authenticated setup within 10 minutes; it cannot activate from a preview deployment of this server.
- `vercel_disable_production` must be an owner-confirmed safe disable path, and revoke the option for future production connections.
- All state changes are durable Postgres operations with bounded expiry and audit. No real-team execution or owner approval inferred from tests.
- Add unit + disposable Postgres tests for two-step, expiry, replay/revocation, preview denial and read-only refusal.

## Implementation evidence for #18

- `src/tools/production-guard.js`: `checkProductionWrite` denies unknown live impact and preview production changes; `requestProductionEnable` on a full-profile preview connection creates only a 10-minute pending one-time reference after explicit confirm, **never enables production**.
- `src/vercel/setup.js`: owner must have authenticated, valid CSRF, and separately re-enter `ADMIN_PASSPHRASE` under database-backed attempt lockout; only a Vercel **production** deployment can consume the approval and set `production_enabled`.
- `vercel_disable_production` requires full-profile connection/confirm, disables the selected account and revokes only its production-mode connector tokens; read-only tools/profiles cannot trigger it.
- `src/core/mcp-server.js`: exact two-name local owner administration allowlist; all other public writes stay default-denied. Tools expose no Vercel credential and make no provider write API call.
- `tests/unit/production-approval.test.js`, `tests/db/production-switch.test.js` cover separate approval, wrong password, expiry, cross-account denial, preview-host refusal, token revocation and profile gating.
