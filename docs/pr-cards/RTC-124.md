# RTC #124 — Bounded batch HTTP response with pass-bound storage

## Drift A
The existing batch endpoint returns ten individually sanitized results but never measured the final envelope, potentially exceeding RTC 1's 8KiB default. DB already supports a 24-hour bounded pass-owned result store and the previous #123 PR added paged GET.

## Acceptance
- No >8KiB batch HTTP reply. A combined response within budget stays inline.
- Over budget, use existing compacted DB store with verified calling account + pass-derived owner; return only safe handle, expiry, count and summary.
- Invalid handle/DB write fails closed; no inline oversized fallback, no unscoped data or other pass reading the result.
- Paged result reads #123 recover the contents with user-controlled safe field selections; respect existing 1MiB store cap.
- Provider tools remain read_only, scoped and rate-debited atomically; no production, spend or hosted D-4 acceptance.
- Exact-head check/unit/db/emulate/ci plus release-policy and self-review.
