# AUD-Y — VMCP-011, second layer: the audit entry is fitted to the record cap, never thrown past a landed write

**Conviction (live, 2026-10-29 closure pass).** AUD-X removed the write executor's per-field post-apply throws, and the VMCP-011 closure probe confirmed the surface shrank — then convicted the next layer with the finding's own repro, twice: `vercel_env_set_many` and `vercel_env_delete_many` with 10 keys at 250 chars on a scratch project both **landed** (read-back proved the keys present, then absent) while the caller received an error envelope: *"Audit record exceeds safe 8 KB limit."* The audit writer (`recordChange` in `src/db.js`) caps the record's **aggregate** JSON — before + after + result + inverse + summary, as it serializes them — at 8192 bytes. A batch whose fields are each ~3 KB passes every per-field bound and still sums past the record cap, and the writer's throw lands after the write has succeeded and verified. (The same probe verified the AUD-U mitigation live: the envelope is now an honest `invalid_request` carrying the real message, not `unknown_error`.)

**Fix.** The executor fits the audit entry before writing it (`fitAuditEntry` in `src/core/write.js`, applied at both audit sites — dry-run and applied): measure the entry exactly as the writer measures it (including the writer's before-wrap of snapshot + targets and its delegation merge into result), and while it exceeds 8192 bytes, replace the largest remaining field (before / after / result / inverse) with its stored reference via the new unconditional `storedReference` helper in `src/core/write-preflight.js`. The summary — the human headline — is never replaced. The writer's cap itself stays: with no result store on the context, `storedReference` throws the same refusal the shaper throws today, and an entry that still cannot fit (a pathological summary) keeps the writer's refusal. Nothing is truncated; every replaced field is recoverable through `vercel_get_result`.

**Tests.** New `tests/unit/write-audit-fitting.test.js`: a write whose before/after/receipt fields are each ~3 KB against an audit double enforcing the production writer's aggregate rule verbatim — the write completes applied/confirmed, the recorded entry measures within the cap with its largest fields as stored references, and the summary survives as text. Small writes are untouched (values throughout, zero store calls); the storeless context still refuses.

**Acceptance.** Unit-proven in this packet. Live closure of VMCP-011 rides the next release: the same oversized env batch must return the applied receipt (or the stored receipt plus handle) — never an error envelope for a landed write.

**Status.** Built 2026-10-29 (this PR). Rides the nightly promotion per the owner's batching rule.
