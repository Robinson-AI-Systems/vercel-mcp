## Build and evidence

`vercel_team_list`: pinned GET /v2/teams (limit 100, no teamId query), filter strictly to encrypted selected team, never enumerate unrelated provider teams. Require selected row or fail closed, refuse duplicates. `vercel_team_get`: pinned GET /v2/teams/{teamId} with ID from stored account, verify provider identity. Project-only credentials denied. Both return allowlisted safe metadata and limited security booleans, no SAML certificates, invitation keys, raw objects or writes. Registered read_only/everyday/full read-only tools.

## O-1b (#145): fully guarded team profile writes

`vercel_team_update_profile` uses pinned PATCH /v2/teams/{teamId}, only with the exact server-held team ID and full owner production connection. Changed fields are limited to safe name, slug, description or preview deployment suffix, validated against pinned OpenAPI. A strong preview warns of team slug's six-change weekly quota and URL changes. After production and protected-target checks plus durable replay, it re-reads scoped account and team state immediately before PATCH and independently GETs intended fields after. The provider's raw team object and potential SAML/invite secrets are never written into audit/output. Tests: `tests/unit/team-profile-write.test.js`, full GitHub Actions. This is code/mock acceptance only, not approval to exercise the live owner account.
