## Build — A-3a (PR 1: primitives and store, no endpoints)

| File | What |
|---|---|
| `src/core/oauth.js` | Copied (first-line source comment): `randomToken`, `hashToken` (SHA-256), `secretsMatch` (timing-safe), `verifyPkce` (S256 only), `validRedirectUri` (https, or http on localhost; no fragments), `clientIp`, `evaluateLogin` with `MAX_FAILED_LOGINS = 5`, `LOCKOUT_WINDOW_MINUTES = 15` |
| `src/db.js` | OAuth store methods on `createDb(sql)`: `createOAuthClient` (secret hashed), `getOAuthClient`, `createAuthCode` (code hashed; stores `vercel_account`, `mode`, `profile`, `listing`), `consumeAuthCode` (single use, `DELETE … RETURNING`, expired → null), `createAccessToken`, `getAccessToken` (revoked/expired → null), `rotateRefreshToken` (one atomic `UPDATE … WHERE refresh_hash = … AND client_id = … AND revoked_at IS NULL RETURNING`, so a replayed refresh token fails), `revokeAccessToken`, `recordLoginAttempt`, `markLoginAttemptSucceeded`, `countRecentFailedLogins`. **One helper** builds every new token row from the issuing row's `connectionSettings()` for both grant types; never a default |
| `test/helpers/fake-db.js` | Same methods in memory (mirror Stripe's fake) |

Tests: `tests/unit/oauth-core.test.js` (PKCE, redirect rules, hash, timing-safe compare, lockout after 5 in 15 min
then allowed after the window); `tests/db/oauth.test.js` on throwaway Postgres: codes single use; tokens stored hashed
(no plain value in any row); revoked/expired refused; refresh only for the same client; refresh keeps `vercel_account`,
`mode`, `profile`, `listing` exactly (`production` row stays `production`, `read_only` stays `read_only`); two
concurrent refreshes with one token → exactly one succeeds; **a test that fails if a column is added to `oauth_tokens`
without being in `CONNECTION_FIELDS` or an explicit non-connection list** (reads `information_schema.columns`).

Authorize page: account dropdown, mode, profile (`read_only` / `everyday` / `full`), listing (`catalog` / `compact`),
passphrase (`ADMIN_PASSPHRASE`; missing → the page says what to set and refuses). Access tokens 1 hour; refresh tokens
rotate on use and work until revoked.

Tests: `tests/unit/oauth-handlers.test.js` (in-process requests with the fake db): register → authorize → token →
refresh end to end; 5 wrong passphrases lock the address (database-counted); a forged `mode=production` POST is refused
when the account is not enabled **and** on a non-production deployment even when enabled (A12); unknown account
refused; missing `ADMIN_PASSPHRASE` fails closed; after a refresh the new token keeps account, mode, profile and listing;
the MCP endpoint refuses a missing, revoked or expired token with 401 and `WWW-Authenticate`.
`tests/db/oauth-persistent.test.js`: the same refresh-keeps-settings flow against throwaway Postgres.
