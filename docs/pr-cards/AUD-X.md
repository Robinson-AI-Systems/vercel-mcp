# AUD-X — VMCP-011's buildable leg: post-apply paperwork can no longer throw a landed write into an error envelope

**Finding.** VMCP-011 (P1, narrowed at S7): an oversized write result (env_set_many, 10 max-length keys) surfaced as a generic `unknown_error` envelope while read-back proved the keys had landed — the write's own verified receipt was never observed live. The read side and the MCP delivery layer already had the stored-result treatment (AUD-D); the write executor's own post-apply path did not.

**Conviction (from source).** AUD-D gave previews and target lists the stored treatment in preflight (`safeShapeStored`: the 8 KB bound displays, it does not block). But in `defineWrite`'s post-apply assembly, the verified receipt (`publicReceipt`), the result, the inverse, and the audit's before/after copies still went through `safeShape` — which **throws** past 8 KB — and the production replay store's `complete()` independently refuses a result over 8192 bytes (`Replay result exceeds the safe storage limit`). Every one of those throws happens *after* the provider write has landed and verified, so the caller receives an error envelope for a completed write and is told to verify by read-back — the observed symptom, exactly. The test doubles never caught it: the suite's replay-store fakes accept any size, and no fixture drove a write whose post-apply paperwork crossed the bound. (The one measurement taken during diagnosis: env_set_many's own fields top out near 3 KB, so the precise live field that crossed remains unidentified — the defect class is proven regardless: any tool whose receipt, verification, or result sums past 8 KB post-apply hits it, and the fix removes the whole class.)

**Fix.** In `src/core/write.js`, everything shaped after the write lands now takes the stored treatment:
- `publicReceipt` and `inverse` go through `safeShapeStored` (stored references when oversized; byte-identical values when they fit).
- The audit's before/after/result copies go through `safeShapeStored` (the audit already holds stored references for targets — same pattern, extended).
- The replay completion receives the `safeShapeStored` form; when that is a stored reference, the receipt scalars (write status, confirmed state, request key) ride beside it, so a replayed answer stays a truthful receipt and always fits the store's cap.
- The returned result is shaped by the new `safeShapeForReturn` (`src/core/write-preflight.js`): the throwing shaper first (byte-identical for everything that fits); on a *size-only* failure it returns the result screened at the storage cap, leaving the display bound to the delivery layer, whose AUD-D path stores it and answers with the receipt plus handle. A shaper refusal for any other reason (secrets, cycles, depth) still throws — nothing is silently truncated, and with no result store on the context the oversized case keeps the original refusal, exactly as AUD-D established.

**Tests.** New `tests/unit/write-stored-result.test.js` drives `defineWrite` with big before/after/receipt shapes against a replay double that enforces the production store's 8192-byte completion cap verbatim: the write completes applied/confirmed, the audit copies are stored references, the completion fits the cap (plain receipt when it fits; reference plus receipt scalars when the result itself stays oversized), small writes are byte-identical with no store calls, and the storeless context still refuses.

**Acceptance.** Unit-proven in this packet. Live closure of VMCP-011 rides the bundle release: the S7 oversized env batch (10 padded keys) must return the applied receipt or the stored receipt plus handle — never an error envelope for a landed write.

**Status.** Built 2026-10-29 (this PR). Bundles with the AUD-I release train per the owner's batching rule.
