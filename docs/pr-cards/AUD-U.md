# AUD-U — VMCP-030: the tools' own validation errors stop collapsing into unknown_error

**Finding.** VMCP-030 (candidate, filed 2026-10-28 during AUD-R): `vercel_project_get` and `vercel_deploy_get` returned `unknown_error` for the VMCP-023 probe run's records while the same records read fine through the write-side operations. The dossier's discrimination (2026-10-28): `vercel_deploy_list` by project NAME errors `unknown_error`, by ID it works — "the failure is illegible but the input was out of contract… a legibility gap."

**Conviction (from source).** Every tool throw funnels through `vercelErrorResult` → `explainVercelError`, whose classifier only recognizes provider codes/statuses. The tools' own curated `TypeError`s — invalid identifiers, identity mismatches (`Deployment outside requested project`), unusable pagination cursors, conflicting record identities — carry neither, so they collapsed into `unknown_error` with the text "The provider did not return a recognized safe error code," blaming the provider for the tool's own refusal. The by-name case is the pure form: a name passes the identifier pattern, Vercel returns rows keyed by the real project ID, the summary projection's identity check refuses — illegibly.

**Fix.** `src/tools/errors.js`: an unrecognized error that is a `TypeError` with no provider status is its own class, `invalid_request`. Its `what` is the error's own message — every such message is written in this repository — surfaced only after the module's safety screens (length cap, no control characters, no credential-shaped content, no secret labels); anything failing the screen falls back to a generic sentence. `why` states the truth: the failure happened on this server while checking the selection or shaping the record; Vercel did not refuse it. `next` points at the exact-ID contract. Provider errors (coded/statused) and generic errors keep their existing classes byte-for-byte. The deployment summary's mismatch message now also names the ID-keyed contract, so the by-name case instructs instead of merely refusing.

**Acceptance.** Unit-proven in this packet (the classifier's three branches + the rendered result). Live closure rides the bundle release: `vercel_deploy_list` by name and `vercel_project_get`/`vercel_deploy_get` on a scratch record must answer `invalid_request` with the naming message — or succeed — never `unknown_error` for a curated refusal.

**Status.** Built 2026-10-29 (this PR). Bundles with the AUD-I release train per the owner's batching rule.
