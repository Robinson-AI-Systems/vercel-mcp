# W-4 — Setup custom domain (Batch W, fourth card)

Design: `docs/designs/BATCH-W.md` §3 row W5, §4 row W-4.
Dossier: `batch-w-dossier-2026-10-30.md` §1 (W-4 row).
Precedent: Batch P verdicts C-1..C-9; W-2/W-3 write composition.

## Scope

`vercel_workflow_setup_custom_domain` (guarded write, PR, full only)
in `src/tools/workflow-domain.js`. Description `{project, domain,
gitBranch?, outsideApp?}`. The design's flow:

1. **Attach** — `vercel_domain_attach_to_project`, skipped when the
   domain is already attached to the project (idempotent: running the
   workflow twice changes nothing the second time).
2. **Config check** — `vercel_domain_check_config` (post-attach
   read-back). When the configuration is already correct, no DNS work
   is planned or done.
3. **DNS steps** — when misconfigured: if Vercel hosts the zone
   (`vercel_dns_list` on the apex succeeds), create the records the
   config read recommends (A records from `recommendedIPv4` at the
   apex; a CNAME from `recommendedCNAME` for a subdomain, else A
   records) via `vercel_dns_create_record`, skipping records the zone
   already has. If Vercel does not host the DNS, the workflow stops
   after attach and returns the exact recommended records as
   needs-you steps — no certificate step runs (the design's rule).
4. **Verify + certificate** — re-check config and the project domain's
   `verified` flag; when verified and no existing certificate covers
   the domain, `vercel_cert_issue` for exactly that name.

## Verdicts recorded on this card

- **W4-C1 (mid-flight steps):** the DNS records' values exist only in
  the post-attach config read, so those steps are derived in `apply()`
  from that read-back, each dispatched through its own guarded
  pipeline with derived request keys continuing the sequence
  (`<key>-s2`, …). The preview states this shape plainly — the owner
  confirms the decision tree, and every step still runs its own full
  pipeline (zone re-read, conflict refusal) when it executes.
- **W4-C2 (external DNS end state):** stopping after attach with
  needs-you records ends the workflow `applied` with
  `confirmed: false` — its own part is done, the domain is not live,
  and the report says exactly which records to create where.
