# O-4 — Billing and activity (reads only)

Status: implemented in this PR. Batch O card 4 of 5 (design: docs/designs/BATCH-O.md §2 O-4, decisions O6; dossier: batch-o-dossier-2026-10-30.md §O-4).

## Scope

- `vercel_billing_list_charges` — FOCUS v1.3 charge lines for a window (default: the current month to date), projected per line: service, provider, category, SKU, project (from the record's Tags), billed and effective cost as integer cents plus a display string, quantity/unit, period. Listing caps at 200 lines with an explicit truncated flag; totals belong to the summary.
- `vercel_billing_list_commitments` — contract commitment records (Enterprise). An empty stream is a valid answer and is reported as such (the Pro credit is not a commitment record).
- `vercel_billing_summary` — the same window totaled: effective and billed totals, credit-category lines, ranked by-service and by-project tables, and the comparison against the stored defaults (Pro monthly credit $20, monthly target $20 — named constants until an owner-settings surface exists, the O-2 seat-price pattern).
- `vercel_activity_list` — the team activity log (`GET /v3/events`): id, time, text, type, principal, entity count. Payloads are never included unless `withPayload` is set, and then only under a size cap.

## Contract facts (pinned snapshot)

- Charges: `GET /v1/billing/charges`, query `from` + `to` REQUIRED, `teamId`/`slug` optional; the 200 response is `application/jsonl` — one FOCUS record per line (required fields incl. BilledCost, EffectiveCost, ChargeCategory enum Adjustment/Credit/Purchase/Tax/Usage, Tags as a string map carrying ProjectId/ProjectName).
- Commitments: `GET /v1/billing/contract-commitments`, also JSONL; category enum Spend/Usage; `ContractCommitmentCost` documented "For Pro: 20 (USD)" when category is Spend.
- Events: `GET /v3/events` → `{events}` of UserEvent (required createdAt ms, entities, id, principalId, text).

## The JSONL read path

The client's normal read path parses `response.json()`, which cannot read a JSONL stream. Following the `streamLogs`/`fileContent` precedent, the client gains an opt-in `{jsonl: true}` mode gated to exactly these two GET operations — any other operation asking for it is refused — decoding through a new bounded line reader (`readBoundedJsonLines` in `src/vercel/bounded-json.js`: 2 MiB cap, content-type screen, no provider payload reflected in errors, malformed line = named `jsonl_stream_invalid` failure).

## IN-12 boundary

Billing here is read/report only. No tool in this card sets or changes a budget, an alert, a pause, a plan, a payment method, or buys credits; the summary's comparison figures are stored defaults labeled as such, and its note points at Vercel Spend Management as the place alerts and controls live.
