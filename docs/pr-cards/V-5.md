## Drift check A — signing, transport and previous run model (2026-10-16)

Reuses V-1 dev_runs and V-2 one_time_secrets authenticated owner reveal. The Vercel webhook contract signs raw request bytes with HMAC-SHA1 and x-vercel-signature; the new event is labeled synthetic and is not attested as originating from Vercel. DNS pins the exact selected preview hostname and rejects private/mixed addresses and redirects. Synthetic receiver and separate real provider acceptance remain unverified until authorized fixtures are available. Bundle freeze is docs/pr-cards/V-4.md; this card does not redefine the planned V-5 criterion.

## Drift check B — run-specific cryptographic purpose

The existing `encryptSecret` AES-GCM AAD purpose validator excludes underscores. V-1 `runId` includes underscores, so raw `dev-webhook:${runId}:webhook-secret` would fail on every real prepare. The scoped purpose is now `dev-webhook:SHA256(runId)[0..32]:webhook-secret`; encryption/decryption use the same derived purpose. Dedicated unit tests cover roundtrip, cross-run failure and absence of raw key in ciphertext. Provider delivery is still PENDING.

## Merge-blocking self-review finding: send is not prepare

The existing generic `oneTimeDelivery` enforced a secret reveal for every invocation of a two-action tool, which caused successful webhook SEND to be returned as outcome_unknown. The provider-neutral `oneTimeWhen` hook now requires owner-only secret reveal on PREPARE only. SEND returns a safe confirmed receipt and never returns any secret. Encrypted key ciphertext is no longer part of the preflight/before object and therefore cannot enter the generic change-log audit or preview; it is reloaded within authorized apply and decrypted only in memory.
