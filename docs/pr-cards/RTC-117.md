# RTC #117 — atomic batch quota accounting

## Drift A
Read-only RTC 1 pass-authenticated HTTPS adapter and DB authorizeRtcPass own all batch reads. The batch has at most 10 tools. No change to MCP OAuth, provider operation parameters, owner pass issuance, spend or resource mutation.

## Acceptance
- Reserve 1 rate unit for each individual tool in batch as one atomic PostgreSQL UPDATE before dispatch.
- 10 tool requests cost 10; no partial provider calls on a quota failure; malformed and oversized batch refused first.
- Single call and existing GETs each cost 1; never accept client-selected costs.
- Two independent DB sessions competing against one pass cannot exceed 60 tool units per rolling minute.
- Preserve preview/read_only area scoping, pass revoke/expiry, and RTC error contracts.
- check/unit/db/emulate/ci green at exact PR head, then final main.
