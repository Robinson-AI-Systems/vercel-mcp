# M-4 — Blob files

Status: in progress · Parent: BATCH-M (`docs/designs/BATCH-M.md`, M4) ·
Dossier: `batch-m-dossier-2026-10-30.md` in the audit goal workspace
(§2 M-4 facts and §4: connection state, the `@vercel/blob@2.8.2`

## What this card builds

- Connection state (new, additive): `blob_store_connections`
  (account, store id, label, access, ciphertext, token last-4).
  The owner connects a store on the setup page (Blob stores
  section: store ID + label + access + read-write token typed
  into a password field); the token is encrypted under its
  (account, store) secret-box context and is listed back only as
  label/store/access/last-4. Disconnect deletes the row; account
  removal cascades to it (dossier S-7). Stores reachable only
  through a project OIDC token cannot be connected in this
  version — the setup copy says so.
- `src/vercel/blob.js` — the repo's documented Blob exception:
  the pinned `@vercel/blob@2.8.2` SDK, always called with the
  connected store's decrypted token (never an ambient env
  token). SDK errors are classified by error-class name into
  plain kinds; provider text never surfaces.
- `vercel_blob_list` (read) — SDK list with the catalog's
  folder summary by default (`folded`; folders + the level's
  files), `expanded` for the flat list; prefix filter; bounded
  cursor paging with the truncation stated when the limit stops
  a longer listing.
- `vercel_blob_head` (read) — one file's metadata (size, type,
  uploaded, cache settings). A missing file answers
  `found: false`, not an error.
- Reads on an unconnected store answer `{connected: false}` with
  the setup steps (IN-15: connection state, not a refusal);
  writes refuse with the same steps.
- `vercel_blob_put` (Cp) — inline base64 ≤4 MB; an existing file
  refuses unless `allowOverwrite`. Production-class when the
  store's linked projects (read through M-3's store read) include
  a production environment — and when linkage cannot be proven
  at all, so an unprovable store is never written to as if it
  were scratch. Verify re-resolves the token and heads the file
  back; the token is never carried in the applied result or the
  replay record (planted-token scans pin this).
- `vercel_blob_delete` (D Cp) — 1–100 exact pathnames; any
  wildcard character refuses the call. The preview lists each
  file with its size (already-absent files are named as such).
  A store connected to any project — or whose linkage is
  unproven — requires `outsideApp: true`: the structural form
  of the design's profiled-store refusal until Batch P's app
  profiles exist. Verify heads every pathname back; the result
  separates deleted from already-absent.
