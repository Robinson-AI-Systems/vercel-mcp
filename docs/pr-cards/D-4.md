## First cohesive release-routing source candidate

Seven approved public tools with pinned official Vercel operations:

- `vercel_alias_list` and `vercel_alias_get`: exact selected project/team alias mappings and bounded metadata, no provider-secret body. Unknown owner, duplicate alias, incomplete v4 listing or ambiguous deployed identity fails closed.
- `vercel_deploy_list_promote_aliases`: latest project promotion status read from pinned GET `/v1/projects/{projectId}/promote/aliases`, capped at 20 safe domain/state pairs; no claim that one snapshot proves final traffic.
- `vercel_deploy_promote`: pinned POST `/v10/projects/{projectId}/promote/{deploymentId}` **only for a staged READY production build that has not already served**. Never promote a preview build, which can require a billed rebuild. Exact project, expected currently serving production deployment and complete alias inventory must be proven twice, with owner confirmation, full production connection, protected/app resource gates and durable replay.
- `vercel_deploy_rollback`: pinned POST `/v1/projects/{projectId}/rollback/{deploymentId}` with a safe optional reason query. Reject an unserved or newer READY build: the target must have independently verified prior serving metadata, earlier creation and matching project/team. Requires exact currently serving deployment; never guesses second newest READY.
- `vercel_alias_assign`: pinned POST `/v2/deployments/{id}/aliases`, reassign **only an already existing owner-verified exact alias** to a READY production target after fresh mapping and revision proof. Does not add a new domain, create a deployment or guess app-ownership.
- `vercel_alias_delete`: pinned DELETE `/v2/aliases/{aliasId}` for an exact existing mapped alias only, full owner production profile, repeat proof before dispatch, and complete selected-project absence readback.

Every mutation classifies as PRODUCTION whether or not domains look like previews, explicitly requires independently owner-enabled production connection, full-profile confirmation, protects team/project/deployments/domains/aliases, reuses existing `defineWrite`, app guard, durable replay and audit, and never spends or initiates a metered build. Writes only report definite success when the new mapping is independently read back; external propagation may remain unknown.
