## Findings

### VMCP-001 — P0 · D1/D2 · The purchase grant is still a product-scope wall for end users
- **Location:** `src/core/write.js` (purchase block), `src/core/write-preflight.js`,
  `src/vercel/spend.js` (`spendPreflight`).
- **Evidence:** any write whose declared spend is > $0, recurring, or unquantified
  cannot be completed by the caller's `confirm`: the executor demands a one-use
  purchase intent approved through separately authenticated owner setup
  (fingerprint-bound, ceiling-checked, expiring), and recurring/unbounded
  metered spend is refused outright outside one narrow Sandbox exception.
  Comment in code: "Agents may only PROPOSE a purchase."
- **Q1–Q3:** (1) limits the *user's* agent on an end-user connection, not only
  builders; (2) a wall — no standing delegation the user can set; (3) the escape
  hatch (per-transaction setup approval) works, but it *is* the ceremony the
  filed IN-08 answer (2026-10-17) declares not full end-user compliance.
- **Disposition:** *Convert* — per the filed answer and remediation issues
  #108–#110, #116, #119: end-user-chosen standing delegation policy per account;
  the one-use grant remains as the user's strictest option and stays mandatory
  for builder/delegated connections. Default strictness → owner packet OP-2.
  **OP-2 RULED 2026-10-27:** optional user-set budget + the owner's word is
  enough, even over their own budget (see the owner packet for the full
  ruled shape). The remediation now has its target design.

### VMCP-002 — P1 · D2 · IN-09: the agent still cannot flip the production switch ON
- **Location:** `src/tools/production-guard.js`, `src/tools/production.js`,
  `src/vercel/setup.js` (`approve_production`).
- **Evidence:** `vercel_enable_production` with `confirm: true` returns
  `awaiting_owner_passphrase` and enables nothing; enable completes only via
  passphrase re-entry on the setup page within 10 minutes. The tool description
  itself says so. `vercel_disable_production`, by contrast, IS agent-completable

- **Q1–Q3:** (1) the user's agent; (2) wall for the ON direction; (3) hatch =
  the ceremony the 2026-10-27 IN-09 ruling superseded as a gate.
- **Disposition:** *Convert* — `confirm` on the owner's full connection completes
  the flip (journal/`recordChange` already exist); passphrase step remains
  available as the owner's chosen strictness and for delegated contexts.

### VMCP-003 — P1 · D2 · IN-04: no token-expiry surface, no notify-ahead

### VMCP-004 — P1 · D2 · IN-12: the server owns spend machinery; Vercel's own spend state is unread

### VMCP-008 — P1 · D1/D10 · The write path has an 8 KB wall with no overflow
- **Location:** `src/core/write-preflight.js` (`safeShape`), `src/core/write.js`
  (audit shaping).
- **Evidence:** previews, target lists and audit summaries are shaped through

### VMCP-009 — P1 · D3 · The default front door is ~15.3K tokens; the 1K compact door is opt-in
- **Location:** `src/db.js` (pass defaults, line ~642: `listing = 'catalog'`),
  `src/core/mcp-server.js` (`listMcpTools`), `scripts/check-budgets.mjs`.
- **Evidence:** probe 1 above. New connections default to the catalog listing
  (everyday ≈ 15,347 tokens by the repo's own tokenizer check, whose budgets

  7 meta/workflow tools, ≈ 1,016 tokens, with search/describe for the rest —

### VMCP-010 — P2 · D3 · Self-shaped tool families bypass the stored-handle path
- **Location:** `src/tools/globalconfig-common.js` (`output()` uses default
  `compact`, 8 KB throw, inside handlers).
- **Evidence:** because shaping happens inside these handlers, an oversized
  result throws before the dispatch-level stored-result fallback can engage —
  this family has no escape hatch where sibling reads do.
- **Disposition:** *Fix* — route self-shaped outputs through the shared
  delivery path (or `prepareResult` + stored fallback).

### VMCP-011 — P1 · D3/D10 · Oversized WRITE results throw after the provider write
- **Location:** `src/vercel/result-delivery.js` (`if (!readOnly) return
  shapeMcpResult(...)`), `src/vercel/shape.js` (default 8 KB `compact`).
- **Evidence:** executed probe 3 — the write path has no stored fallback, so a
  write whose result exceeds 8 KB returns a hard error to the caller even
  though the provider write was dispatched and journaled. The journal saves
  the truth, but the response contract breaks failure honesty: the caller
  cannot tell from the response that the write landed.
- **Disposition:** *Fix* — give write results the same stored treatment, or
  return the verified receipt (the `publicReceipt` machinery is the seed)
  with a handle to the full body.

  amendment). The finding's substance (no undo tool; thin compound layer) is

## S2 — Owner packet (the only items needing Chris's ruling)

**OP-1 — Default front door (from VMCP-009). RULED by Chris, 2026-10-27:**
"Compact plus the most commonly used tools and compound tools on the front
page, budget is 5,000 tokens." The prediction (compact as default) was
accepted and extended by the ruling: the front door is a curated set —
compact meta tools + measured most-used tools + compound tools — capped at
5,000 tokens total. S4 designs the exact membership from usage evidence.

**OP-2 — Standing purchase delegation default (from VMCP-001).** The IN-08
remediation needs the *default* shape for end-user connections: (a) standing
ceiling the user sets (agent buys under it with confirm + journal),
(b) approve-all standing policy (confirm + journal only), or (c) per-transaction
one-use grants remain the default, with (a)/(b) as opt-ins the user can set.
*Prediction: (c) as the shipped default for delegated connections, with the
owner's own full connection free to choose (a) or (b) as a standing setting* —
strictest default where a delegate spends someone else's money, owner's own
choice where it's his.
**RULED by Chris, 2026-10-27:** a combination of the allowance and the
standing yes, in his words: "user giving the agent a budget (optionally),
but also their word is enough — even to override their own budget." The
ruled shape: the budget is **optional** and user-set; it governs the agent's
own discretion (and frames the cost disclosure), but the owner's explicit
instruction to purchase executes on their word — under the budget, over the
budget, or with no budget set — journaled, with the in-chat confirm/preview
flow as the confirmation. The mandatory per-transaction setup-page grant is
retired as the end-user path. Scope note, per his standing doctrine: the
word that overrides is the *account owner's*; on delegated/builder
connections the owner's budget binds the delegate, and only the owner
overrides it. (The prediction's (c) default was superseded — the owner
chose the combination instead; the miss is kept on the record.)

Everything else in this register takes its disposition from decisions already
filed (IN-04/08/09/11/12/15, END-USER-AUTHORITY) and the lens — no further
rulings needed to proceed to S3/S4.
